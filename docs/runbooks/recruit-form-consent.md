# Runbook: 応募フォームに越境移転の同意設問を追加する

- 対象: 採用応募に使っている Google フォーム（`careers.html` の `#apply` からリンク）
- 起点: 2026-08-13 の 2周目クロスレビュー「careers の同意がどこにも記録されない」
- 実施者: **人間**（下記「なぜ Claude が実行しないか」参照）
- 所要: 2〜3 分

## なぜ必要か

同意ルート（個人情報保護法28条1項）を選んだ以上、**同意を得たことの立証責任は当社にある**。

現状:

| 経路 | 同意の取得 | 同意の記録 |
|---|---|---|
| お問い合わせフォーム | サイト上のチェックボックス | ✅ `consent=agreed` が Formspree の送信データに残る |
| 採用応募フォーム | サイト上のチェックボックス（`#apply` のゲート） | ❌ **どこにも残らない**（JS がリンクを解錠するだけ） |

サイト側のゲートは「同意しないと米国へ遷移させない」までは担保しているが、
**誰がいつ同意したかの証跡がゼロ**。Pマーク審査でも同意の実在を示せない。

→ **フォーム側に設問を 1 つ足せば、回答として保存されるので証跡になる。**
サイト側のゲートは残したまま二重化する（どちらかに寄せない）。

## 手順0（先にやること・重要）

**このフォームの所有者は `rbl4job@gmail.com`（無償の Google アカウント）である**（2026-08-13 に Drive API で実測）。

無償アカウントには Cloud Data Processing Addendum が適用されず、Google は処理者ではなく
自らの目的で取り扱う管理者として振る舞う。**この状態では「Google LLC へ取扱いを委託している」という
`privacy.html` の整理が成立しない。**

→ **設問を足す前に、フォームを `@mdx-inc.co.jp`（Google Workspace 契約テナント）所有へ移す。**
   同ドメインの MX は `smtp.google.com` で、Workspace テナントは実在することを確認済み。
   移管は Google フォームの「共有」→ オーナー権限の譲渡で行う。
   移管できない事情がある場合は、設問追加より先に `privacy.html` の記載を実態に合わせる必要がある
   （＝ houmu-check を1本通す。「委託」ではなく第三者提供として整理し直すか判断する）。

## なぜ Claude が実行しないか（2026-08-13 実測）

- `~/.secrets/gworkspace-ops/tokens/osawa_drive_write.json` に `drive` scope の
  リフレッシュトークンが**存在する**。当該フォームに対して Drive API の `capabilities.canEdit` は **true**。
- `forms.batchUpdate` は `drive` scope で通る仕様（discovery document で確認）。
- **ただし Forms API が GCP プロジェクト `435543667942` で有効化されていない**（`forms.get` が 403
  `Google Forms API has not been used in project ... before or it is disabled`）。
- API の有効化は GCP コンソールの操作にあたり、グローバル方針で「明示指示時のみ可」としているため、
  Claude は自発的に行わない。**有効化の指示があれば API 経由で実行できる。**

> 以前この runbook には「保存済みトークンが無いため Claude は実行できない」と書いていたが、
> これは非再帰の glob で `tokens/` を見落とした誤りだった（2026-08-13 に訂正）。

## 追加する設問（この文言をそのまま使う）

- **位置**: フォームの **一番最初**（他の設問より前）
- **質問文**:
  ```
  個人情報の越境移転への同意
  ```
- **説明文**（質問の説明欄に入れる）:
  ```
  この応募フォームは Google LLC（アメリカ合衆国）が提供しており、ご入力いただいた内容は同社のサーバに保管されます。アメリカ合衆国では連邦レベルでの包括的な個人情報保護法令が存在せず分野別の個別法が適用されること、同国がAPEC越境プライバシールール（CBPR）システムの参加国であること、同社が講じている措置などの詳細は、当社プライバシーポリシー「外国にある第三者への提供（越境移転）について」（https://mdx-inc.co.jp/privacy.html#third-party）をご確認ください。ご同意いただけない場合は、郵送でのご応募も承ります（神奈川県横浜市都筑区川和町2330-2 MDX株式会社 採用担当）。
  ```
- **回答形式**: **ラジオボタン（単一選択）**
- **選択肢**: `同意します` の **1 つだけ**
- **必須**: **ON**

> チェックボックスでも必須にすれば最低1つの選択を強制できる。ラジオボタンにするのは
> **回答値が1つに定まり、集計・監査がしやすいため**。
> 選択肢を「同意します」1 つに絞れば、必須ラジオ＝同意しないと送信できない構成になる。

## 手順

1. 応募フォームを編集モードで開く
   - <https://docs.google.com/forms> を開き、一覧から **「MDX株式会社 採用応募」** を選ぶ
   - ⚠ `careers.html` の `data-href` にある `/d/e/1FAIpQLS…/viewform` の URL は
     **回答者用 ID** で、`/edit` に置き換えても 404 になる（編集用 formId とは別物・2026-08-13 実測）
2. 最初の設問の上に新しい質問を追加する（左のツールバーの ⊕）
3. 上記の質問文・説明文・回答形式・選択肢を入力する
4. 右下の **必須** を ON にする
5. 設問を先頭へドラッグする
6. プレビュー（👁）で、**未選択のまま送信できないこと**を確認する

## 確認

- プレビューで「同意します」を選ばずに送信 → **エラーになる**こと（＝ゲートが効いている）
- 送信すると `同意します` が記録されること（回答スプレッドシート未連携なら「回答」タブで確認する）
- **確認のために送信したテスト回答は「回答」タブから削除する**（応募データに空レコードを残さない）

## やらないこと

- **サイト側のゲートを外さない。** 規則17条2項は「同意を得ようとする時点」の情報提供を求めるため、
  遷移前に自社ページで情報提供＋同意を取る構成は維持する。フォーム側は証跡のための二重化。
- **同意の回答を prefill しない。** Google フォームは URL パラメータで回答を事前入力できるが、
  同意を代わりに入れてしまっては同意の記録として無意味になる。必ず応募者本人に選ばせる。
