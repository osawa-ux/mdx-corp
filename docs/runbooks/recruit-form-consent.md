# Runbook: 応募フォームを Workspace へ作り直し、越境移転の同意設問を追加する

- 対象: 採用応募に使っている Google フォーム（`careers.html` の `#apply` からリンク）
- 起点: 2026-08-13 の 2周目クロスレビュー「careers の同意がどこにも記録されない」。
  2026-08-16 に**オーナー権限の移管が Google 仕様で不可**と判明し、設問追加 runbook から
  **作り直し runbook** へ範囲を拡大した（下記「手順0」）
- 実施者: **人間（手順 A・C）＋ Claude（手順 B、および C の検証）**
- 所要: 人間の作業 10〜15 分

## なぜ必要か

同意ルート（個人情報保護法28条1項）を選んだ以上、**同意を得たことの立証責任は当社にある**。

現状:

| 経路 | 同意の取得 | 同意の記録 |
|---|---|---|
| お問い合わせフォーム | サイト上のチェックボックス | ✅ `consent=agreed` が Formspree の送信データに残る |
| 採用応募フォーム | サイト上のチェックボックス（`#apply` のゲート） | ❌ **どこにも残らない**（JS がリンクを解錠するだけ） |

サイト側のゲートは「同意しないと米国へ遷移させない」までは担保しているが、
**誰がいつ同意したかの証跡がゼロ**。Pマーク審査でも同意の実在を示せない。

→ **フォーム側に設問を 1 つ足せば、回答として保存されるので証跡になる。**
サイト側のゲートは残したまま二重化する（どちらかに寄せない）。

## 手順0（先にやること・重要）— 2026-08-16 全面改訂

**このフォームの所有者は無償の個人 Google アカウント（代表者本人の旧アカウント）である**
（2026-08-13 に Drive API で実測、2026-08-15 に再実測して継続を確認）。
連携する**回答スプレッドシートも同じアカウント所有**で、応募者の実データはそちらに蓄積される。

この状態では `privacy.html` の「Google LLC へ取扱いを委託している」という整理が成立しない
（法27条5項1号の委託該当性は取扱いの実態で決まるところ、Google 利用規約が無償アカウントの
コンテンツについて自社目的での利用を許容しているため。詳細は houmu-check 2026-08-15）。

> ❌ **オーナー権限の移管はできない。試みないこと。**
> Google 公式ヘルプ（EN/JA 両版）に「個人の Google アカウントから職場または学校のアカウントを
> 使用しているユーザーには、ファイルのオーナー権限を譲渡できません」と明記されている。
> <https://support.google.com/drive/answer/2494892>
> **人間が操作しても成功しない。** 旧版の本 runbook は「共有 → オーナー権限の譲渡で行う」と
> 書いていたが、これは実行不能な手順だった（2026-08-16 訂正）。

→ **正しい手順は「作り直し」。** `@mdx-inc.co.jp` の **共有ドライブ**で新しいフォームを作成し、
   `careers.html` のリンクを差し替える。**同意設問は新フォームの作成時に一緒に入れる**（下記「追加する設問」）。
   決定の正本は `docs/decisions/0001-recruit-form-workspace-migration.md`。

**個人ユーザーの「マイドライブ」ではなく共有ドライブに置くこと。** 個人所有のままだと
退職・アカウント削除で同じ事故が再発する。共有ドライブなら組織が所有者になる。

## なぜ Claude が実行しないか（2026-08-16 時点）

Claude は**新フォームを作成できない**。理由は API 権限であって、以前書いていた「トークンが無い」ではない。

- mail-ops のドメイン全体の委任（DWD）サービスアカウントで `info@mdx-inc.co.jp` を
  impersonate できることは実測済み（`gmail.modify` で疎通・陽性対照）。
- **ただし同テナントで Drive / Forms の scope が認可されていない**（`drive` `drive.metadata.readonly`
  `forms.body` はいずれも `unauthorized_client`）。scope の追加は Google 管理コンソールの操作で、
  グローバル方針の「明示指示時のみ可」に当たる。
- したがって既定の経路は**人間が Workspace UI で作成する**（下記「手順」）。
  管理コンソールで scope を追加する指示が出れば、Claude が API で作成できる。

> ⚠ **現フォームへの同意設問追加（旧タスク②）は着手しないこと。**
> Forms API を有効化して現フォームに設問を足しても、フォームは旧個人アカウント所有のままで
> 問題は解決しない。新フォームへ差し替えるならその作業は捨てになる。
> 旧記述にあった GCP プロジェクトでの Forms API 有効化は、作成経路が確定するまで凍結。

## 追加する設問（この文言をそのまま使う）

- **位置**: フォームの **一番最初**（他の設問より前）
- **質問文**:
  ```
  個人情報の越境移転への同意
  ```
- **説明文**（質問の説明欄に入れる）:
  ```
  この応募フォームは Google LLC（アメリカ合衆国）が提供しており、ご入力いただいた内容は同社のサーバに保管されます。アメリカ合衆国では連邦レベルでの包括的な個人情報保護法令が存在せず分野別の個別法が適用されること、同国がAPEC越境プライバシールール（CBPR）システムの参加国であること、同社が講じている措置などの詳細は、当社プライバシーポリシー「外国にある第三者への提供（越境移転）について」（https://mdx-inc.co.jp/privacy.html#third-party）をご確認ください。ご同意いただけない場合は、郵送でのご応募も承ります（神奈川県横浜市都筑区川和町2330-2 MDX株式会社 採用担当）。
  ```
- **回答形式**: **ラジオボタン（単一選択）**
- **選択肢**: `同意します` の **1 つだけ**
- **必須**: **ON**

> チェックボックスでも必須にすれば最低1つの選択を強制できる。ラジオボタンにするのは
> **回答値が1つに定まり、集計・監査がしやすいため**。
> 選択肢を「同意します」1 つに絞れば、必須ラジオ＝同意しないと送信できない構成になる。

## 手順（人間・所要 10〜15 分）

**A. 新フォームを作る**

1. `info@mdx-inc.co.jp`（Google Workspace）でログインする。
2. <https://drive.google.com/drive/shared-drives> を開き、採用用の**共有ドライブ**を選ぶ（無ければ作る）。
   ⚠ 個人の「マイドライブ」に作らないこと（手順0 参照）。
   ⚠ **共有ドライブが表示されない／作成できない場合は、そこで停止して報告すること。**
   共有ドライブは一部のエディション（Business Starter 等）では利用できず、また管理コンソールの
   設定で作成が制限されている場合がある。**マイドライブで代替しない**（個人ユーザー所有になり、
   退職・アカウント削除で同じ事故が再発するため）。エディションと管理者設定の確認が先。
3. 共有ドライブ内で「新規 → Google フォーム」を作成し、名前を **「MDX株式会社 採用応募」** にする。
4. 旧フォームの設問を新フォームへ書き写す。
   - 旧フォームは <https://docs.google.com/forms> の一覧から開く（旧アカウントで開く必要がある）。
   - ⚠ **旧アカウントは別のブラウザプロファイル（またはシークレットウィンドウ）で開き、
     `info@mdx-inc.co.jp` のウィンドウと混在させないこと。** 同一ウィンドウでアカウントを
     切り替えると、どちらのアカウントで操作しているかを取り違えやすく、次項の
     「コピーの所有者はコピーした人になる」事故を誘発する。
   - ⚠ `careers.html` の `data-href` にある `/d/e/1FAIpQLS…/viewform` は**回答者用 ID** で、
     `/edit` に置き換えても 404 になる（編集用 formId とは別物・2026-08-13 実測）。
   - 設問数が少なければ手打ちで足りる。旧フォームで「コピーを作成」しても**コピーの所有者は
     コピーした人**になるため、必ず `info@mdx-inc.co.jp` 側で作成・コピーすること。
5. **上記「追加する設問」を先頭に入れる**（質問文・説明文・ラジオ・選択肢1つ・必須 ON）。
6. 回答先スプレッドシートを作成し、**同じ共有ドライブ内**に置く。
7. プレビュー（👁）で、**未選択のまま送信できないこと**を確認する。
8. 「送信」→ リンクアイコンから**回答者用 URL** を取得し、Claude へ渡す。

**B. サイト側の差し替え（Claude が実施）**

9. `careers.html` の `#apply-link` の `data-href` を新 URL へ差し替える。
10. 旧フォーム ID が repo 全体・本番ページから 0 件になることを確認する。
11. Drive API で新フォームの所有者が共有ドライブであることを実測する。

**C. 旧フォームの後始末（人間・Claude 併走）**

12. 旧フォームの「回答を受け付ける」を **OFF** にする。
13. 旧回答スプレッドシートの内容を新側へコピーする。

> 🛑 **手順14（削除）の前に、次の2つを両方満たすこと。片方でも欠けたら削除しない。**
> 旧フォームは**無償の個人アカウント**所有のため、ゴミ箱を空にすると
> **Workspace 管理者による復元経路が存在せず不可逆**になる。
>
> - **(a) 件数照合**: 新側スプレッドシートの応募レコード数が旧側と一致すること
>   （2026-08-15 実測時点で **2 件**。実施時点の旧側件数を数え直して照合する）。
> - **(b) 法29条の一括記録台帳が作成済みであること**（ADR 0001 実施順序2）。
>   旧スプレッドシートは記録事項（本人の氏名等・個人データの項目）の**原資料**であり、
>   台帳を作る前に消すと記録義務を果たす手段を同時に失う。
>   ⚠ 台帳は本人の氏名を含むため **public な本 repo には置かない**。

14. (a)(b) を満たしたら、**旧スプレッドシートと旧フォームを削除し、ゴミ箱も空にする**
    （無償個人アカウント領域に応募者データを残さない）。
15. 旧フォームの編集者権限のうち**個人 gmail アカウントを削除する**。
16. `privacy.html` の応募フォームに関する記述を「提供」→「委託」へ戻すか再判断する。
    ⚠ **Formspree, Inc. は移行後も「提供」のまま**。一律に戻さないこと（ADR 0001 実施順序6）。
    ⚠ 戻す前に、Google が当該データを自社目的に利用しない旨が実態として担保されていることを
    確認すること（委託該当性は契約書の有無ではなく取扱いの実態で決まるため）。

## 確認

- プレビューで「同意します」を選ばずに送信 → **エラーになる**こと（＝ゲートが効いている）
- 送信すると `同意します` が記録されること（回答スプレッドシート未連携なら「回答」タブで確認する）
- **確認のために送信したテスト回答は「回答」タブから削除する**（応募データに空レコードを残さない）
- 新フォームの Drive 上の所有者が**共有ドライブ**であること（Drive API で実測）
- 旧フォーム・旧スプレッドシートが削除済み（ゴミ箱も空）であること

## やらないこと

- **サイト側のゲートを外さない。** 規則17条2項は「同意を得ようとする時点」の情報提供を求めるため、
  遷移前に自社ページで情報提供＋同意を取る構成は維持する。フォーム側は証跡のための二重化。
- **同意の回答を prefill しない。** Google フォームは URL パラメータで回答を事前入力できるが、
  同意を代わりに入れてしまっては同意の記録として無意味になる。必ず応募者本人に選ばせる。
