# 0001: 応募フォームのオーナー権限移管を断念し、Workspace 共有ドライブでの作り直しに切り替える

## Context and Problem Statement

`privacy.html` §5「外国にある第三者への提供（越境移転）について」（`id="third-party"`）は、Google LLC を含む外国事業者へ個人情報の取扱いを**委託**していると記載して公開している。

しかし採用応募フォームおよびその回答スプレッドシートの所有者は、当社の Google Workspace テナントではなく**代表者本人の旧個人アカウント（無償 Google アカウント）**である（2026-08-13 に Drive API で発見、2026-08-15 に再実測して継続を確認）。

2026-08-13 時点の整理は「オーナー権限を @mdx-inc.co.jp へ移管すれば『委託』の記述が実態に追いつく」であり、移管は現所有者のログインを要する人間作業として保留していた。2026-08-15 の調査でこの前提が崩れた。

### 判明した事実（2026-08-15 実測）

1. **オーナー権限の移管は Google の仕様上できない。** Google 公式ヘルプ（英語版・日本語版の両方）に「個人の Google アカウントから職場または学校のアカウントを使用しているユーザーには、ファイルのオーナー権限を譲渡できません」と明記されている。人間が操作しても実行できず、「人間限定タスク」ではなく**実行不能タスク**だった。
   - <https://support.google.com/drive/answer/2494892>
2. **回答スプレッドシートも同じ無償個人アカウント所有**である。応募者の実データはフォーム本体ではなくこちらに蓄積される。移管対象はフォーム単体ではない。
3. 当該スプレッドシートの**応募レコードは 2 件**（件数のみ取得。セルの値は読んでいない）。移行負担は小さい。
4. `info@mdx-inc.co.jp` は**実在する Google Workspace ユーザー**である（既存のドメイン全体の委任による代理アクセスで疎通確認）。移行先テナントは実在する。
5. 上記の代理アクセスに使っているサービスアカウントは、**当社 Workspace テナントで Drive / Forms の権限が認可されていない**（メール権限を陽性対照にして切り分け済み）。API 経由でフォームを作るには管理コンソールでの権限追加が要る。

### 法務確認の結果（houmu-check 2026-08-15）

- 法27条5項1号の**委託該当性は契約書（DPA）の有無ではなく取扱いの実態で決まる**。2026-08-13 の「CDPA が適用されないから委託が成立しない」という理由づけは誤りだった。
- ただし**結論は変わらない**。Google 利用規約（発効日 2026-07-30）は無償アカウントのコンテンツについて、サービスの運営・改善（自動化されたシステムによる解析を含む）および新技術の開発という**Google 自身の目的での利用**を許容している。「委託された業務の範囲内でのみ」を満たさず、実態は法28条1項の**第三者提供**である。
- **法29条の記録義務は、公開文書での用語選択ではなく取扱いの実態で決まるため、すでに発生している。** 2026-08-13 に「『委託』と書いておけば記録義務が発生しない」として書き換えを見送った判断は、法的前提が成り立たない。
- 記録は、当該第三者へ**継続的又は反復して提供したとき（若しくは提供することが確実であると見込まれるとき）**に限り、規則19条2項ただし書により**一括作成が可能**である。本件は応募フォームが常時稼働しており同要件を満たす。保存期間は最後の提供日から 3 年（規則21条2号）。必要事項は同意取得済みの旨・提供先の名称・住所・代表者氏名・本人の氏名等・個人データの項目（規則20条1項2号）。**提供年月日は必要事項に含まれない**（それは法27条2項オプトアウト提供の場合のみ）。
  - 規則19条・20条・21条は e-Gov 法令 API（`428M60020000003`）で逐語確認した。
- 回答全文は Obsidian `30_Areas/houmu-qa/answers/2026-08-15-mdx-form-itaku-seiritsu.md`。

## Considered Options

- **案A: オーナー権限を移管する** — Google 仕様により実行不能。検討対象から外れる。
- **案B: `privacy.html` を「提供」と断定する表記に書き換え、フォームは現状維持** — 記載は正確になるが、応募者の個人情報が当社の安全管理措置の及ばない個人アカウント領域に残り続ける。法23条の観点で不適切。
- **案C: @mdx-inc.co.jp の共有ドライブでフォームを作り直し、リンクを差し替える。あわせて `privacy.html` の記載を実態に合わせ、法29条の一括記録を作成する** — 移行完了後は、Google が Workspace の顧客データを自社の目的に利用しない旨を約しており、**取扱いの実態が委託の範囲内に収まる**ため委託が成立し、「委託」表記が実態に追いつく。将来分の記録義務も消える。
  - ⚠ この判断の根拠は **Cloud Data Processing Addendum が適用されること自体ではなく、それによって担保される取扱いの実態**である（上記のとおり委託該当性は契約書の有無では決まらない）。移行後に表記を戻す際は、実態を再確認してから戻すこと。
- **案D: Google フォーム以外の基盤へ移す** — 委託契約を締結できる基盤なら成立するが、選定・実装コストが応募 2 件の規模に見合わない。

## Decision Outcome

**選択: 案C。**

理由: 案A は実行不能。案B は記載の正確性しか回復せず、個人情報の所在という本質的な問題（法23条・法25条）が残る。案C だけが「記載の正確性」と「安全管理措置の及ぶ範囲への回収」を同時に満たし、かつ移行完了後は記録義務そのものが将来に向けて消える。応募レコードが 2 件しかないため移行コストが小さいことも案C を支持する。

### 実施順序

1. ~~`privacy.html` §5 の「委託」を差し替える~~ **✅ 2026-08-16 実施済（commit `c4fa42d`・本番反映・CI green を sha 一致で実測）**。
   ⚠ 実装は**中立表記ではなく、経路ごとの書き分け**になった。応募フォーム（Google）と問い合わせフォーム（Formspree）は「提供」と明記し、業務用メール（Google Workspace）は「委託」と明記して、委託でも外国にある場合は法28条1項の同意が要る旨を添えている。§7「外的環境の把握」も、提供し切ったデータは対象外であることに合わせて是正済み。
   → **案B（「提供」と断定する表記）のうち記載の是正部分は、結果的に先行して実施された状態にある。** 案B を却下したのは「記載だけ直してフォームを個人アカウントに残す」点であり、記載の是正自体は案C の第一歩として必要だった。
2. 法29条の**一括記録台帳**を作成する。⚠ 本人の氏名を含む＝応募者の個人情報のため、**public な本 repo には置かない**。保管場所を決めてから作成する。
3. @mdx-inc.co.jp の**共有ドライブ**でフォームを作り直す（個人ユーザー所有にしない。退職・アカウント削除で同じ事故が再発するため）。
4. `careers.html` の応募リンクを新フォームへ差し替える。
5. 旧フォームの回答受付を停止し、旧データをコピー移行したうえで旧ファイルを削除しゴミ箱も空にする。編集者権限の個人アカウント 2 件を削除する。
6. 移行完了後、`privacy.html` の**Google（応募フォーム）に関する記述のみ**「委託」表記へ戻すか再判断する。⚠ **Formspree, Inc. は移行後も「提供」のまま**である（同社は利用規約で自らを "separate and independent data controllers" と規定しており、当社が Workspace へ移っても同社の立場は変わらない）。一律に戻すと今回の是正が逆行するため、経路ごとに判断すること。

### Consequences

- Good: 応募者の個人情報が当社の安全管理措置の及ぶ範囲に入る。移行後は委託が成立し、法29条の記録義務が将来に向けて消える。Pマーク J.9.4（委託先の特定・監督）の指摘リスクが下がる。
- Good: 応募フォームの同意設問追加（別タスク）を新フォーム作成時にまとめて実施でき、二度手間にならない。
- Bad: 応募フォームの URL が変わる。外部の求人媒体等に旧 URL を掲載していれば差し替えが要る。
- Bad: 移行が完了すると応募フォームは委託になるため、`privacy.html` の当該記述を再度書き換えることになる（計 2 回）。
- Bad: 一括記録台帳という新しい管理対象が増える（保存 3 年）。移行完了までの分は消えない。
- Bad: 案C の実施には Google 管理コンソールまたは Workspace アカウントでの人間の操作が要る。Claude だけでは完了できない。

## Confirmation

- 移管が不能であることの確認: 上記 Google 公式ヘルプの記載。人間が試行しても成功しないため、成功を完了条件にしない。
- 移行完了の確認: 新フォームの Drive 上の所有者が共有ドライブ（@mdx-inc.co.jp テナント）であることを Drive API で実測する。旧ファイルが削除済み（ゴミ箱も空）であることを実測する。
- `careers.html` の差し替え確認: 旧フォーム ID が repo 全体および本番ページから 0 件になること。
- `privacy.html` の確認: 本番ページに中立表記が反映されていること。
- 記録台帳の確認: 規則20条1項2号の必要事項がすべて記載されていること。保存期間の起算日（最後の提供日）が記録されていること。
