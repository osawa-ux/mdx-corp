# 0002: public repo の git 履歴に残る識別子・個人アドレスの扱い

## Context and Problem Statement

本 repo は **public** である。`_config.yml` の `exclude:` により `docs/` は公式ドメイン（`mdx-inc.co.jp`）からは配信されず 404 になるが、**GitHub 上（`raw.githubusercontent.com` を含む）では誰でも読める**（2026-08-16 実測: 公式ドメイン 404 / raw 200）。

現在の HEAD から退避しても、git の履歴には残る。該当は **3 類型**ある。

> ⚠ **本 ADR は public repo に置くため、意図的に抽象度を上げて記述している。**
> 対象ファイル・commit sha・値そのものは書かない。**詳細の正本は非公開台帳**
> （Obsidian vault `20_Projects/mdx-corp/index.md` および同 `cloudflare-identifiers.md`）に置く。
> 公開文書に所在を書くと、「履歴に埋もれている」状態から「検索可能なポインタ付き」状態へ
> 実害度を上げてしまい、本 ADR 自身の「実害が小さい」という前提を掘り崩すため。

### 件1: Cloudflare のアカウント固有識別子（2026-08-13 起票・期限 2026-08-20）

- 過去版の runbook に、アカウント固有の 32 桁識別子（zone id / ruleset id）が複数含まれていた。
- **現 HEAD にアカウント固有値は無い**（2026-08-16 実測）。残る 32 桁値は Cloudflare の**権限グループ ID** で、Cloudflare が公開 API エンドポイントから取得可能なものとして文書化しており、秘匿値としては扱われていない。アカウント固有値はプレースホルダに置換され、実値は非公開台帳にある。
  - ⚠ **未確認**: 権限グループ ID が全アカウントで同一値かは一次資料で確認できていない（公式ドキュメントは値を列挙せず、API から取得せよとしている）。「秘匿値ではない」ことは確認済みだが、「全アカウント共通」は未検証。
- これらの識別子は**それ単体では認証に使えない**（API トークンが別途必要）。作業に使った一時トークンはゾーン限定・2 権限のみで、適用後に削除して残存 0 件を確認済み（2026-08-13）。

### 件2: 代表者本人の個人フリーメールアドレス（2026-08-16 発見）

- 過去版の runbook に、応募フォームの所有アカウントとして**生のアドレスで**記載されていた。
- repo の `CLAUDE.md` 運用ガード §4「repo は public なので secret・個人情報（スタッフの個人連絡先を含む）はどこにも書かない」に反する。
- **HEAD からは本 ADR と同一 commit で除去する**（「代表者本人の旧アカウント」という抽象表現へ置換）。履歴には残る。
- 当該アドレスは**代表者本人のもの**であり、患者情報でも社外第三者の個人情報でもない。第三者の権利利益を侵害する性質のものではない。
- ⚠ ただし当該アカウントは、移行が完了するまでの間**応募者の個人情報を含むスプレッドシートのオーナー**である。アドレスが判明していることは、標的型フィッシングやアカウント乗っ取りの起点になりうる。**この経路は ADR 0001 の移行完了によって消える**ため、移行の優先度を上げることが最も効果的な緩和策である。

### 件3: アカウント固有識別子とローカル secret レイアウトの開示（2026-08-16 発見）

- 過去版の runbook に、GCP プロジェクト番号 1 件と、ローカルの secret 配置パス 1 件（ファイル名に代表者の姓を含む）が記載されていた。
- **HEAD からは本 ADR と同一 commit で除去する。** 履歴には残る。
- いずれも単体では認証に使えないが、secret の配置規則が分かることは攻撃者にとって探索コストを下げる。
- ⚠ **件1 の 32 桁 hex 検査でも件2 のアドレス検査でも捕捉されない類型**である（下記 Confirmation 参照）。

## Considered Options

- **案A: 履歴を受容する（HEAD の清潔さのみ維持し、以後の混入を防ぐ）**
- **案B: `git filter-repo` 等で履歴を書き換え、force push する**
- **案C: repo を private 化する** — 本サイトは GitHub Pages で配信しており、**無償プランでは private repo から Pages を配信できない**。有料プランへの移行か配信基盤の変更を伴うため、履歴衛生のためだけに採る手段としては過大。

## Decision Outcome

**選択: 案A（受容）。ただし件2 については、代表者本人の意向で案B に切り替えてよい。**

理由:

- **案B の効果が限定的である。** 過去の実測（vault `git-history-phi-purge`）で、**force push では PR の ref が消えない**こと、GitHub 側にキャッシュされた blob が残りうることが分かっている。「消えた」と考えて運用を戻すと、実際には残っている状態で安心することになり、かえって危険。
- **案B のコストが実在する。** force push は全クローンを壊し、CLAUDE.md の standing go の対象外で院長ゲートに当たる。本 repo は共同編集者（write 権限 1 名）がおり、巻き込みが起きる。
- **漏えいの実害が小さい。** 件1・件3 は単体で認証に使えない識別子で、件1 の対応トークンは削除済み。件2 は代表者本人のアドレスで、第三者の権利利益に関わらない。
- 一方、**件2 は本人の個人情報**であり、本人が消したいと判断するなら尊重されるべき性質のもの。ここは技術的合理性ではなく本人の意向で決めてよい。

### やること（案A を採る場合）

1. HEAD の清潔さを維持する（3 件とも本 ADR と同一 commit で達成する）。
2. 件1 の一時トークンは削除済みのため**ローテート不要**。追加対応なし。
3. **件2 の緩和は ADR 0001 の移行完了**（応募者データを当該アカウントから引き上げる）で行う。移行までの間、当該アカウントの 2 段階認証が有効であることを確認する。
4. 以後の混入防止は pre-push guard に委ねる。ただし現行 guard は secret / PHI パターン検査であり、**フリーメールアドレスは検知対象外**（件2 はガードを通過して公開された）。→ 下記 Confirmation の検査を追加する。

### Consequences

- Good: 全クローンを壊さず、共同編集者を巻き込まない。「消えたつもりで消えていない」誤認を作らない。
- Good: 件1 のトークンは既に削除済みで、追加のローテート作業が発生しない。
- Bad: 履歴を参照すれば識別子と個人アドレスは読める状態が続く。
- Bad: Pマーク審査で git 履歴まで確認された場合、指摘の材料になりうる（可能性は低いが、ゼロではない）。

## Confirmation

**commit 直後に HEAD に対して実行し、結果を記録すること**（本 ADR の記述は同一 commit での除去を前提としているため、commit 前の実行では偽になる）。

- 32 桁識別子: `git grep -nE '[0-9a-f]{32}' HEAD -- docs/` の結果が、Cloudflare 権限グループ ID のみであること。
- フリーメールアドレスの不在: `git grep -niE '[a-z0-9._%+-]+@(gmail|googlemail|yahoo|ymail|outlook|hotmail|live|msn|icloud|me|mac|aol|proton(mail)?|gmx|zoho|docomo|ezweb|au|softbank|i\.softbank|nifty|biglobe|ocn|so-net)\.' HEAD` が 0 件であること。
- 件3 の類型: `git grep -nE '\.secrets/|/tokens/' HEAD -- ':!docs/decisions/'` が 0 件であること。
  ⚠ 検査対象から `docs/decisions/` を除外しているのは、**本 ADR 自身が検査パターンを本文に含むため**（除外しないと常に自己マッチして赤くなる）。guard に実装する際も同じ除外が要る。
  GCP プロジェクト番号相当（12 桁前後の裸の数字列）は誤検知が多いため自動検査に含めず、**レビュー時の目視対象**とする。

**pre-push guard の拡張**（別タスク）:

- 上記フリーメール検査と `\.secrets/` 検査を guard に追加する。
- **わざと混入させた入力で赤くなることを実測**してから有効とみなす（陽性対照。exit code だけで判定しない）。
- ⚠ 前提として明記すべき既知の限界が 2 つある。①本 repo の `pre-push` は `.git/hooks` 配下の未追跡ラッパーで、本体は共有スクリプト＝**インストール済みの端末でのみ効く**。write 権限を持つ共同編集者のクローンでは有効とは限らない。②guard は `remote_sha..local_sha` の端点 diff を見るため、**push 範囲の途中 commit で追加され最終 commit で削除された値は検知しない**。

**案B を選ぶ場合の完了条件**: 書き換え後に**別クローン**で `git log -S` を実行して 0 件を確認する。**PR ref は force push で消えないため、PR の有無を併せて確認する**。
